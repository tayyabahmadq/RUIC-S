## 1. WHAT I BUILT

folder-06 is the Leader, the orchestration brain of the multi-model plugin.
It exports `Leader` (plan, route, verify, signOff) and `ReviewQueue`
(decide, ratify, veto) plus `CommonsError`. The Leader decomposes brief +
goalState into sequential tasks through exactly one LLM call via the
transport (modelId = crew.lead), routes tasks to engineers while never
assigning an already-claimed path, drains conflicts once by re-routing or
splitting, verifies each goalState criterion through exactly one LLM call
against the merged WORKSPACE, and signs off with a sha256 over the final
WORKSPACE file map, emitting `run.completed`. Every state change flows
through `commons`; the Leader holds no in-memory truth, so a new instance
restarting from the same COMMONS resumes in place. `zod` validates LLM
JSON; all other dependencies are Node built-ins. Working stubs for every
cross-part dependency live in src/stubs.ts so this part builds and tests
standalone.

## 5. PROVIDES TO OTHERS

Import { Leader, ReviewQueue, CommonsError } from parts/folder-06.
- Leader: owns the run lifecycle — plan() → route() → verify() → signOff().
  Pass PlanInput to plan() (or pre-write folder-06:brief/goalState/crew into
  commons), pass criteria to verify() (or pre-store folder-06:verifyCriteria).
- ReviewQueue: workers call decide(); a diff touching more than one file
  enters status 'pending'; integrator/lead calls ratify() to settle or
  veto(reason) to convert the reason into a routed follow-up task.
  Construct with the same commons + bus instance the Leader uses so decision
  state is shared.
- CommonsError: catch and inspect { code, folder: 'folder-06', detail? }
  for all failures from this part.

## 8. INTEGRATION NOTES

- Node >= 20, TypeScript strict, CommonJS emit into dist/. Runtime
  dependencies: zod only. Tests: node:test; compiled output is tested, so
  no TS runtime loader is needed.
- plan() resumes: if folder-06:tasks is non-empty, plan() returns the stored
  tasks and skips the LLM call. Crash-restart with the same commons resumes.
- verify() needs criteria: the caller derives them from goalState and passes
  them (preferred), or stores folder-06:verifyCriteria first. verify() with
  neither throws LEADER_NO_CRITERIA.
- Split semantics (recorded as simplest interpretation): a conflicted task
  with no free engineer is replaced by <path>.part-1 and <path>.part-2 with
  the next sequential ids; each part is claimed normally. The conflict is
  marked resolution 'split' in one drainQueue pass; no second pass.
- decide() with touched.length <= 1 is ratified immediately (simplest
  interpretation: single-file diffs need no review). touched.length > 1
  enters status 'pending'.
- Veto follow-up task id comes from the plan task counter
  (T-NN continuation), so ids stay sequential across the run.
- Stub transport returns deterministic canned JSON (plan: 2 tasks keyed off
  the brief; verify: satisfied=false when the criterion contains 'fail').
  Replace with a real LLM transport for production.
- No `any` is used anywhere. File names are kebab-case.
- COMMONS is append-only: nothing is ever deleted by this part.
- Standalone fix (implementation detail, no public interface change): `src/stubs.ts` `listClaims()`/`list()` now cast `cloneDeep` results to `Claim[]`/`Conflict[]`, and the module-level `nowIso()` helper is defined; `src/leader.ts` imports the `Claims` type. These were gate fixes only.

## 9. DO NOT CHANGE

Invariants that must survive integration:

- Public exports keep their names and shapes: Leader, ReviewQueue,
  CommonsError, TaskSchema, plus the types listed in section 3.
- Leader constructor deps shape: { transport, commons, claims, conflicts,
  bus } with the interfaces in src/types.ts.
- Every LLM call goes through transport.completion; every state change goes
  through commons; the Leader holds no in-memory truth.
- Task ids are sequential T-01, T-02, ...; every task has exactly one
  non-empty WORKSPACE-relative path.
- route() never assigns a path that is already claimed; drainQueue resolves
  every recorded conflict exactly once (re-route to a free engineer or split).
- verify() makes exactly one LLM call per criterion.
- signOff() checksum = sha256(JSON.stringify(sorted map of path ->
  sha256(file content))); emits 'run.completed' with { checksum, fileCount,
  at }.
- CommonsError: code: string, folder === 'folder-06', optional detail.
- File names kebab-case; runtime dependency surface limited to zod.
- COMMONS append-only invariant: nothing is ever deleted.

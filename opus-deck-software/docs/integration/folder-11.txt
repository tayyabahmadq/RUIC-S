=====================================================================
1. WHAT I BUILT
=====================================================================
folder-11 implements the precision diff-review agent: a deterministic
selection → bundling → rule matching → positioning → reflection pipeline
that reviews WORKSPACE changes with near-zero false-alarm rate and feeds
findings into the existing STATE/findings.json → escalation → ReviewQueue
loop. No model convenience-choice can silently skip a file: every
non-excluded file appears in at least one bundle (asserted in code),
and every dropped finding is recorded with its reason (positioning or
reflection only).

The agent is orchestrated by ReviewAgent.review(request), which:
  a) collects the file list (explicit paths or DELTA/txn-log scope from WORKSPACE),
  b) filters exclusions (non-text/binary, over size cap, held-claim paths,
     vendored/generated globs),
  c) bundles files (same-stem test/file pairs, dir-sibling config grouping,
     token-budgeted with folder-04's estimateTokens),
  d) calls the f02 transport once per bundle via ReviewAgent (NOT the
     f07 task/claim queue — R3),
  e) positions findings to exact lines via content match,
  f) reflects (second-pass confirm/deny) per bundle,
  g) persists findings to STATE/findings.json via the wiring layer,
  h) escalates unpatchable criticals to the ReviewQueue,
  i) emits review.requested / review.bundle.started / review.bundle.done /
     review.completed on the shared hub,
  j) writes STATE/folder-11/reviews/<runId>.json audit record.

  escalationQueue.push(escalation) → ReviewQueue.
- folder-01 (scaffold): event hub — emits review.requested, review.bundle.*,
  review.completed on the shared hub (R2: new event names, additive).

8. INTEGRATION NOTES
=====================================================================
- folder-11 does NOT import across folder boundaries at runtime; all
  collaborators are constructor-injected via ReviewAgentDeps (wiring layer
  resolves them). Folder numbers in §4 are assumptions; the interface is
  the contract.
- R1: folder-11 consumes folder-04's estimateTokens for bundle budgeting.
  No second estimator is written inside f11.
- R2: review.* event names are NEW members of the f01 EventName/EventPayloads
  closed set; existing events are never repurposed. PROVENANCE event catalog
  updated accordingly.
- R3: review LLM calls go directly through folder-02's Transport.complete.
  They do NOT enter the f07 task/claim queue. The optional claim on reviewed
  paths stays optional and advisory.
- R4: unpatchable-critical findings escalate to the ReviewQueue; veto produces
  a follow-up task whose path is decision.touched[0], a real claimable
  WORKSPACE path.
- Positioning + reflection are the ONLY reasons a finding may be dropped.
  Every drop is recorded with its reason in ReviewDrop.
- STATE/folder-11/reviews/<runId>.json answers "did the reviewer skip it?"
  for every file, every bundle, every finding.

=====================================================================
1. WHAT I BUILT
=====================================================================
folder-12 implements the workspace knowledge-graph memory: a deterministic
detect → extract → build → cluster → section pipeline that turns the
WORKSPACE source tree into a file→symbol→import graph, clusters it from
the entry points, ranks hub files by in-degree, and renders a compact
CODEMAP digest section that reaches the planner/worker prompt through
the normal digest slot (slot 2 of the five-slot prompt). No AST or
tree-sitter: scoped regex extraction + structure conventions only.

createCodegraph(deps) → { rebuild(), load() }:
   a) walks the source tree under the memory directory,
   b) classifies each file's role from path conventions (entry/module/
      test/config/doc) — no parsing library,
   c) extracts imports (import ... from, import, require, dynamic
      import, export ... from) and exported symbols per file with
      scoped regex; deterministic and CRASH-SAFE per file,
   d) assembles the graph: relative imports resolve in-tree, externals
      drop to a count, same-directory files get sibling edges,
   e) clusters by entry-point BFS traversal and ranks hubs by in-degree,
   f) renders the CODEMAP section (top hubs, orphan list, cluster
      table, external count) trimmed to the token cap,
   g) writes STATE/folder-12/codegraph.json + STATE/folder-12/report.md
      and the CODEMAP section into STATE/digest.md — all through the
      commons write path, so delta/compaction semantics apply unchanged,
   h) emits codegraph.rebuilt { files, clusters, hubs } on the shared hub.

5. PROVIDES TO OTHERS
=====================================================================
- createCodegraph(deps).rebuild(): full scan → graph → CODEMAP digest
  section → state files → codegraph.rebuilt event. Returns
  CodegraphResult (files/clusters/hubs counts, the graph, skipped paths).
- createCodegraph(deps).load(): the last built graph from
  STATE/folder-12/codegraph.json, or null when none exists.
- STATE/folder-12/codegraph.json — nodes, edges (imports + sibling),
  externalCount, generatedAt.
- STATE/folder-12/report.md — human-readable report: counts, skipped
  files (with the crash-safety probe's logged skips), hubs, clusters,
  orphans.
- The CODEMAP section inside STATE/digest.md — consumed by any prompt
  that takes the digest slot (slot 2 of the five-slot prompt).
- fingerprintSourceTree(root) — deterministic source-tree fingerprint
  used by the wiring hook's rate limiting.

6. CONFIG
=====================================================================
No environment variables. Token cap: CodegraphDeps.tokenCap, defaulting
to 500; wiring passes the digest-token budget (config.budgets.digestTokens,
default 2000). Section content is trimmed from the end until it fits the

test/config/doc patterns are hard-coded path conventions in detect.ts.

8. INTEGRATION NOTES
=====================================================================
- folder-12 does NOT import across folder boundaries at runtime; all
  collaborators are constructor-injected via CodegraphDeps (the wiring
  layer resolves them). Folder numbers in §4 are assumptions; the
  interface is the contract.
- R1: folder-12 consumes folder-04's estimateTokens for the CODEMAP
  token cap. No second estimator is written inside f12.
- R2: codegraph.rebuilt { files, clusters, hubs } is a NEW member of
  the f01 EventName/EventPayloads closed set with a NEW payload type;
  existing events are never repurposed. PROVENANCE event catalog
  updated accordingly.
- R6: CODEMAP is REGENERABLE STATE, not pinned memory. Compaction may
  demote the CODEMAP digest section — that is correct behavior; the
  next rebuild restores it. CODEMAP is never added to PINS. Both
  directions are covered by tests: (a) a compaction run with a CODEMAP
  section present produces a valid digest, (b) a rebuild after such
  compaction restores the section.
- CRASH-SAFETY: extraction is per-file isolated. A file whose read
  fails, or whose content is malformed as text (NUL byte), yields a
  logged skip (console + result.skipped + report.md) — never a failed
  rebuild. The crash-safety probe proves a workspace with one malformed
  file still rebuilds a complete graph.
- Rebuild triggers: the explicit CLI surface (`deck codegraph build`,
  registered in the Phase-10 command table; the rebuild itself runs
  through the wired composition root WiredDeck.f12.rebuildCodegraph,
  consistent with the declarative command table) AND a wiring-
  registered, rate-limited hook on commons write events: the hook
  filters to paths under the source tree only and is fingerprint-
  gated, so identical states never rebuild.
- v1 BOUNDARY: no tree-sitter/AST parsers (heavy, brittle). Regex
  extraction + structure conventions are enough for hubs/orphans/
  dead-code candidate reporting. An AST backend may later slot behind
  extract.ts without schema changes (FileExtraction is the seam).

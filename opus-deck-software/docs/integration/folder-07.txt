1. WHAT I BUILT
folder-07 implements the engineering crew runner: budgeted five-slot prompt assembly, a per-engineer worker loop that claims tasks, acquires locks, streams model output, parses the write-intent wire format, writes through COMMONS as the model author, releases locks, and emits completion/failure events; a runCrew pool that shares one task queue across N workers and retires a worker after 3 consecutive failures; and a per-model 12-entry LRU working set exposed for the compactor. All cross-part dependencies are duck-typed and replaced in src/stubs.ts, so the package runs standalone with Node's built-in test runner and zero runtime dependencies except zod. Every failure throws CommonsError with folder "folder-07". The completion/failure contract is exposed as bus events named task.completed, run.failed, compaction.requested, compaction.done, and worker.retired (plus engineer.retired and crew.worker.retired aliases).

8. INTEGRATION NOTES
buildPrompt is synchronous; compaction is therefore assumed synchronous: emitting compaction.requested triggers the stub bus to synchronously emit compaction.done, then slot 5 is trimmed. A real async bus must either call compaction synchronously or have compaction done before buildPrompt returns. It is impossible to await inside a synchronous signature.
EngineerWorker reads BRIEF.md, STATE/digest.md, and STATE/presence.json through commons.read; if read is unavailable or parsing fails, the corresponding field degrades gracefully to empty.
Task claim sets come from Task.claimSet first, then Task.locks.
Duck-typed dependency methods are called with .call so their this binding is preserved.
Write-intent parsing accepts a fenced JSON block or surrounding prose and one corrective retry; the retry uses a corrective system note.
Transport output chunks are normalized for string, text/content, delta.content, and OpenAI-style choices[0].delta.content.
A task that fails is marked failed in its own queue entry; unstarted tasks remain pending so they naturally stay available to other workers.
Retirement emits worker.retired, engineer.retired, and crew.worker.retired with modelId, consecutiveFailures, and returnedTaskCount when available.
runCrew's third argument accepts either CrewDependencies or { dependencies, concurrency }; concurrency is accepted for compatibility but the current implementation runs all N workers concurrently.
Use default stubs for standalone testing; the integrator may pass real dependencies through constructor or runCrew.
EngineerWorker.read commons data assumes the above conventional paths; adjust if the integration uses different path names.
The LRU default instance is process-global and per-model namespaced.

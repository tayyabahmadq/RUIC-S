=====================================================================
1. WHAT I BUILT
=====================================================================
folder-02 implements the model registry and the ONLY LLM-calling transport
layer of the system. ModelRegistry registers ModelRefs and resolves API keys
with the mandated order: env var named by apiKeyEnv -> keystores/<model id>
file -> typed CommonsError (API_KEY_MISSING). Three Transport adapters
(openai-compatible, anthropic, custom) stream SSE into a uniform
TransportChunk stream ({text}|{usage}|{done}) with the mandated retry policy:
exponential backoff 250ms * 2^n, max 4 attempts, only on 429 / 5xx / network
errors, never on other 4xx, AbortSignal respected immediately. UsageTracker
keeps per-model and run-wide token sums as clean integers for the dashboard,
and streamWithUsage records usage automatically while forwarding chunks.
healthCheck(id) probes each model with a 1-token non-streaming completion and
returns {ok, latencyMs, detail} without throwing on provider/key failures.
The folder never decides when a call happens; it only executes complete().

6. CONFIG
=====================================================================
folder-02 parses no config file of its own. Config arrives through the
RegistryConfigSource seam (section 4). Runtime knobs:

env vars (not fixed names):
  <apiKeyEnv>                    type: string   default: none
      Name is chosen per ModelRef via `apiKeyEnv`; if set and non-empty after
      trim, it is the API key. Checked BEFORE the keystore file.
  process.env                    type: EnvSource default: process.env
      Overridable for tests via RegistryOptions.env.

files/dirs:
  keystoreDir                    type: string   default: `<cwd>/keystores`
      One file per model id: `<keystoreDir>/<keystoreFileName(id)>`
      (path separators and Windows-reserved chars `/\:*?"<>|` replaced with
      `__`). File content trimmed; empty file = absent. Gitignored.

RegistryOptions keys:
  keystoreDir  string          default `<cwd>/keystores`  see above
  env          EnvSource       default process.env         env lookup source
  fetch        FetchLike       default globalThis.fetch    HTTP seam/tests

AdapterOptions keys (constructor of each adapter):
  ref           ModelRef        required              model + endpoint + wire name
  apiKey        string          required              bearer/x-api-key value
  fetch         FetchLike       default global fetch  HTTP seam/tests
  retry         Partial<RetryPolicy> default DEFAULT_RETRY_POLICY (test seam; production must omit)
  includeUsage  boolean         default true (openai-compatible) / false (custom)
                                request `stream_options.include_usage`

CreateTransportOptions keys: retry, includeUsage (same semantics as above).

ModelRef keys: id (string, unique), provider ('openai-compatible'|'anthropic'|'custom'),
endpoint (absolute URL), model (wire name), apiKeyEnv? (string), maxTokens?
(positive int), temperature? (0..2), headers? (Record<string,string>, merged
last into request headers).

8. INTEGRATION NOTES
=====================================================================
Decisions made where the brief was ambiguous (simplest interpretation):
a) register(ref) on a duplicate id throws MODEL_ALREADY_REGISTERED (no
   silent overwrite). get()/list() return defensive copies.
b) API key resolution is synchronous (readFileSync) — key files are tiny and
   read at createTransport() time. Empty/whitespace-only values count as
   absent. File name for ids containing `/`, `\`, `:` etc: see
   keystoreFileName(). One file per model id, content trimmed.
c) healthCheck(id) = one non-streaming POST with max_tokens=1 (costs one
   token) with a 10s internal timeout. Provider/auth failures return
   { ok: false, latencyMs, detail } (never throw); only unknown ids throw
   MODEL_NOT_FOUND. Missing key -> ok:false, detail starts 'API_KEY_MISSING:'.
d) Retry: attempt n+1 delay = 250 * 2^n ms (250, 500, 1000 before attempts
   2,3,4). No jitter. Once any chunk has been yielded, the attempt is not
   retried (prevents duplicated text). Provider error events inside a
   stream (PROVIDER_STREAM_ERROR) are NOT retried (not 429/5xx/network).
   `retry` option exists only as a test seam; omit in production.
e) complete() ignores req.modelId for wire selection; the bound
   ModelRef.model is sent. req.modelId is used only for usage attribution
   (streamWithUsage) and diagnostics. Adapters are stateless; reuse is safe.
f) openai-compatible/custom emit exactly one done chunk, last, exactly once.
   finishReason is the provider-native string; missing -> 'stop'. Usage
   accepted as {prompt_tokens,completion_tokens} or {input_tokens,output_tokens}.
   openai-compatible sends stream_options.include_usage=true by default
   (disable with includeUsage:false for picky gateways); custom never sends it
   and tolerates zero usage events.
g) anthropic: req.system and any system-role messages are joined with '\n\n'
   into the top-level `system` field; at least one non-system message is
   required (else INVALID_REQUEST). max_tokens defaults to 4096. finishReason
   = stop_reason verbatim ('end_turn', 'max_tokens', ...); missing -> 'end_turn'.
   Usage is emitted at message_stop (or stream end) combining input_tokens
   from message_start and output_tokens from message_delta. Only text_delta
   content blocks are surfaced (no tool_use handling in this folder).
h) Malformed SSE JSON throws TRANSPORT_STREAM (fail loudly, no silent data
   loss). SSE comments/keep-alives are ignored. `[DONE]` is honored for
   OpenAI-shaped streams and ignored elsewhere.
i) UsageTracker: every record() increments calls by 1 (streamWithUsage records
   once per usage chunk; models whose provider emits no usage show calls: 0).
   Values are floored, non-finite/negative -> 0; totals() returns copies.
j) zod is used for register()/complete() runtime validation. Unknown object
   keys are stripped (tolerant for config extras), bad types throw typed
   CommonsError (INVALID_MODEL_REF / INVALID_REQUEST).
k) The transport must not be handed an empty apiKey: constructor throws
   API_KEY_MISSING immediately (fail fast at wiring time).
l) No files are written by this folder at runtime; keystores/ is only read.
   The COMMONS directory is not touched by folder-02 at all.
m) Assumption recorded: folder-01 is assumed to own config/COMMONS loading
   for the RegistryConfigSource seam (section 4). If another folder owns it,
   only the stub instance is replaced; the interface is unchanged.

9. DO NOT CHANGE
=====================================================================
Invariants that must survive integration:
1. Transport interface exact shape: `complete(req: CompletionRequest):
   AsyncIterable<TransportChunk>`; TransportChunk is exactly the 3-member
   union {text}|{usage}|{done}. Never add methods/fields to Transport.
2. CommonsError exact shape: name 'CommonsError', code: string (values from
   ErrorCodes), folder === 'folder-02', optional detail. Every failure in
   this folder is a CommonsError; nothing throws bare Errors to callers.
3. ModelRegistry API names/signatures as in section 3; resolution order
   env -> keystores -> API_KEY_MISSING must stay.
4. Retry constants: baseDelay 250ms * 2^n, maxAttempts 4, retry ONLY 429/5xx/
   network; never other 4xx; AbortSignal honored immediately (backoff included).
5. UsageReport numbers are finite non-negative integers; totals() must remain
   render-ready with zero sanitization on the dashboard side.
6. Adapters implement Transport and are stateless per complete() call.
7. Chunk ordering guarantees: text chunks in provider order, usage chunk(s)
   after text they describe, exactly one final done chunk.
8. keystoreFileName() mapping for unsafe id characters and the
   `<keystoreDir>/<sanitized model id>` layout (existing key files must keep
   working after integration).
